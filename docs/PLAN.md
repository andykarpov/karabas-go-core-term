# term — современный терминал для Karabas Go / Mini / Mini G — план

## Цель

Ядро-терминал: эмуляция уровня современных терминалов (`TERM=xterm-256color`), Unicode (UTF-8, широкие символы),
сеть через модуль ESP8266 на плате (telnet, SSH), а также USB CDC (последовательный порт через MCU, getty на ПК).

## Решения пользователя (2026-11-18)

- Эмуляция xterm-256color (не VT100 / VT105), Unicode, софт-ядро CPU + прошивка на C.
- Транспорты: telnet и SSH через ESP8266, USB CDC.
- Кодировки кроме UTF-8 (для BBS и старых хостов).
- Репозиторий `andykarpov/karabas-go-core-term` ПРИВАТНЫЙ, id ядра `term`.
- Наши ядра core-vt100 и pdp2026 (vt10x) за основу не берём и не смотрим.

## Решения Claude (пока не подтверждены пользователем)

- **CPU: VexRiscv rv32im** с кэшами, как в core-doom (там SoC, SDRAM, SRAM, HDMI, kg_mcu2 уже работают на всех трёх
  платах); тулчейн xPack riscv-none-elf-gcc 15.2.0-1 в `~/opt`, ISS и Verilator-стенд из core-pico8 / core-doom.
- **Движок терминала: libvterm** (MIT, C99, движок терминала neovim): разбор ECMA-48 / xterm, UTF-8, 256 цветов и
  truecolor, альтернативный экран, scroll regions, DECSET, мышь xterm, bracketed paste. Своих ячеек у libvterm много
  (толстые) — видео получает компактные ячейки через damage-callback'и libvterm.
- **Telnet: libtelnet** (Sean Middleditch, public domain) или свой минимальный: IAC, ECHO, SGA, TTYPE (`xterm-256color`),
  NAWS (размер экрана), BINARY.
- **SSH: кандидат wolfSSH + wolfCrypt** (GPL-3, есть клиент, рассчитан на встраиваемые без ОС); запасные — libssh2 +
  mbedTLS / свой клиент на monocypher (curve25519, ed25519, chacha20-poly1305). Выбор по замеру Ф0 (время handshake,
  размер кода, лицензия по дереву исходников).
- **Видео: 1024 x 768 @ 60 (65 МГц)** — проверено в core-atari2600 на LX25-2 (1280 x 720 там не сошёлся по таймингу).
  Шрифт 8 x 16 → **128 x 48**; широкие символы 16 x 16 (две ячейки). На Go — VGA тем же таймингом (проверить в Ф1).
  Запасной режим 640 x 480 (80 x 30) — пункт OSD, если монитор не берёт 1024 x 768.
- **Шрифт: GNU Unifont** (8 x 16 и 16 x 16 для широких, весь BMP, GPL-2+ с font exception / OFL — проверить в Ф0)
  + по желанию Terminus для латиницы / кириллицы (OFL). Шрифт целиком в памяти платы (~2 MB), глифы по номеру кодовой
  точки через таблицу.
- **Рендерер в RTL**: на каждую текстовую строку — чтение строки ячеек в line buffer (BRAM), на каждую строку пикселей —
  строки глифов из памяти; цвета: палитра 256 в BRAM + truecolor в ячейке; атрибуты bold / italic (наклон сдвигом) /
  underline / reverse / blink / dim / strike, курсор (блок / подчёркивание / черта, мигание). Ячейка 8 байт:
  глиф 21 бит, fg / bg (индекс или RGB), атрибуты, флаг широкого.
- **Память**: код и куча в SDRAM (через кэши), шрифт и экранный буфер — в SRAM или SDRAM (решить в Ф0 по полосе:
  128 ячеек x 8 байт на строку текста + 128 строк глифов по 2–4 байта на строку пикселей). Scrollback (Shift+PgUp) в SDRAM.
- **ESP8266 со стоковой AT-прошивкой**, без своей прошивки (её используют tsconf, next, zxuno, OSD Wi-Fi). Wi-Fi
  настраивается в `app_wifi` OSD boot-ядра, в ядре — только статус. Предпочтительно режим с кадрами `+IPD` (не
  прозрачный): ESP всегда остаётся в командном режиме, закрытие соединения видно (`CLOSED`), выход из ядра посреди
  сеанса не ломает следующим ядрам AT. Скорость UART — 115200 с CTS (`AT+UART_DEF` в ESP не трогаем); поднять скорость
  только через `AT+UART_CUR`, если сброс ESP при выходе из ядра надёжен (Go / Mini: ESP_RESET_N — вывод ПЛИС;
  Mini G: только MCU `board_reset_peripherals()`, сейчас вызывается лишь для пункта OSD «Reset...»).
- **USB CDC**: последовательный порт MCU (кадры UART в kg_mcu2, скорость DLL / DLM от ПК) — второй транспорт, на нём
  отлаживается парсер (getty на ПК).
- **Кодировки**: UTF-8 (по умолчанию), CP437 (ANSI-арт BBS), CP866, KOI8-R, CP1251, ISO-8859-1 — таблицы в прошивке,
  выбор на запись в телефонной книге и в OSD.
- **Клавиатура**: HID-отчёт от MCU → последовательности xterm (стрелки, F1–F12, Home / End, режимы курсора DECCKM),
  раскладки US / RU (переключение Alt+Shift или Ctrl+Shift), ввод UTF-8. Мышь — режимы мыши xterm (SGR 1006).
- **Интерфейс подключения** (свой экран в терминале): телефонная книга (хост, порт, протокол, кодировка, логин),
  ручной ввод, статус Wi-Fi / IP; хранение на SD (как сохранения core-doom: образ / `kg_bk_ram`, решить в Ф0).
  Внешний вид экрана подключения и OSD — кадр пользователю и его «да» до мержа.
- **SSH-безопасность (обязательно, не backlog)**: источник энтропии (TRNG на ПЛИС нет: кольцевые генераторы в ПЛИС +
  джиттер событий клавиатуры / UART / таймингов ESP, сбор в пул, хэш), хранение и проверка ключей хостов (known_hosts
  на SD, отпечаток при первом подключении, предупреждение при смене ключа). Вход по паролю, затем по ключу (ed25519,
  ключ на SD).
- Звонок (BEL) — короткий тон в DAC / HDMI audio, по желанию визуальный.

## Ф0 — замер (go / no-go), почти без платы

Ветка `f0-measure`, один PR в конце.

1. **libvterm для rv32im**: сборка, прогон в ISS на записанных потоках (вывод `vim`, `htop`, `mc`, `cat` UTF-8-текста,
   `vttest`) → байт в секунду разбора при 60–80 МГц. Порог: не меньше скорости канала с запасом (115200 = 11.5 KB/s,
   цель ≥ 100 KB/s для USB CDC и будущей скорости ESP).
2. **SSH**: сборка кандидата (wolfSSH + wolfCrypt) для rv32im, лицензия по дереву исходников, размер кода, время
   handshake в ISS (curve25519 + ed25519 + chacha20-poly1305 / aes-ctr). Порог: подключение ≤ 10 с при 60–80 МГц,
   пропускная способность шифра ≥ скорости канала.
3. **ESP AT на плате** (без ядра: с ПК через `AT+KARABAS=esp`, тикет hwq, сказать пользователю): `AT+GMR`, режим
   `+IPD` против прозрачного (8-битная чистота: 0xFF, `+++` внутри данных), как сообщается закрытие соединения с той
   стороны, приём при CTS, `AT+CIPSEND` предельный размер, задержки.
4. **ESP после смены ядра**: кто и когда сбрасывает ESP (прошивка: только Mini G и только «Rese...»); что видит
   следующее ядро, если term вышел посреди сеанса. Решение: какой режим AT и какая скорость допустимы.
5. **Видео и площадь**: XST VexRiscv + рендерер + SDRAM / SRAM + kg_mcu2 на 1024 x 768 (клоки как в atari2600:
   VCO 650 МГц), оценка LUT / BRAM, полоса памяти рендерера.
6. **Загрузка**: как прошивка (~0.5–1 MB) и шрифт (~2 MB) попадают в память — в `.kg` (docs/kgo2.md в tools, пределы
   размера и время загрузки) или файлом с SD (FL, как WAD в core-doom); где хранить телефонную книгу и known_hosts.

Результат Ф0: таблица замеров + строка go / no-go по каждому пункту, уточнённые решения в этом файле.

## Ф1 — Mini G: терминал на USB CDC

SoC (VexRiscv, SDRAM, SRAM, HDMI 1024 x 768, kg_mcu2), рендерер, libvterm, клавиатура HID с раскладками US / RU,
транспорт USB CDC. Проверка: getty на ПК, `TERM=xterm-256color`, vim / htop / mc, UTF-8-тексты, `vttest`. OSD: схема
цветов, курсор, режим видео.

## Ф2 — сеть: ESP8266 и telnet

Драйвер AT (неблокирующий), статус Wi-Fi / IP, telnet с согласованием опций, экран подключения + телефонная книга на
SD, кодировки (CP437 / CP866 / KOI8-R / CP1251 / ISO-8859-1), звонок. Проверка на telnet-BBS и на своём хосте.

## Ф3 — SSH

Клиент SSH (пароль, затем ключ ed25519), энтропия, known_hosts на SD, экран отпечатка / смены ключа. Мышь xterm,
scrollback, bracketed paste (если не вошли раньше).

## Ф4 — Go / Mini, релиз

Топы Go / Mini (VGA на Go, сброс ESP выводом ПЛИС), сборка всех плат (map -t 2), README en / ru, релиз в karabas-go
(cores.json) — только если пользователь решит открыть ядро (сейчас репозиторий приватный).
